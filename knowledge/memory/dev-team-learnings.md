Cross-project lessons from dev-team runs. Project-specific findings stay in each repo's `.claude/dev-team/team-memory.md`. Code-level bug-class lessons (specific coding/testing defects, e.g. money-path safe-integer checks, focus-visible contrast) live in `~/os/skills/dev-team/review-standards.md` → "Known Failure Patterns" instead — this file is orchestration/process only.

- 2026-07-09 Fixture/UI tests that select an element by first-match query (regex/DOM position) silently match the wrong one once a change adds more of the same element type inside a repeating component. **How to apply:** match test selectors by content (visible text, aria-label), never by DOM position.

- 2026-07-17 Repo-wide sweeps (pattern rewrites, style/vocab passes, grep/banned-pattern tests) must cover every authored file, not just published/active ones, and get their blast radius pre-audited — grep for assertions the sweep will break and patch them in the same commit. Self-scan sweep tests must also exclude `.claude/`: nested dev-team worktrees are full checkouts of the same repo, so a self-scan passes in a worktree but fails in the main checkout whenever any sibling worktree exists, reading as a false regression. **How to apply:** scope sweep greps to the full source directory; grep test files for anchors on the pattern being swept and update them alongside the change; add `.claude` to every sweep test's skip list at authoring time.

- 2026-07-09 `claude -p --bare` removes the Skill tool from the model's tool list entirely — any eval rung relying on skill-augmented behavior silently gets zero skill access. Separately, headless one-shot eval tasks must use pure unit tests, not integration tests requiring a live dev server, since a check needing `npm run dev` fails on infra, not logic, in a subprocess that exits immediately. **How to apply:** never use `--bare` for skill-dependent eval rungs; probe flags empirically before building an eval harness against them; verify any headless eval check completes with the server stopped, or convert it to a unit test.

- 2026-07-17 A correction pass (factual fix, copy fix) tends to miss downstream summary surfaces (about pages, READMEs, config descriptions) that echo the same value — engineers scope the edit to files containing the error, not every file that echoes it. Separately, an engineer reframing a flagged claim tends to assert an unbuilt capability as a present-tense guarantee, because it's reasoning about desired positioning, not shipped features. **How to apply:** for any factual/copy-correction item, instruct the engineer to grep all summary/description surfaces for the old value; review-check that every present-tense capability claim maps to a feature that exists in the repo.

- 2026-07-28 A `dt-*` agent's report can go missing silently at either of two points: the agent never writes `*-report.md` (only returns findings in its final message), or the orchestrator writes but never commits it and a later `git checkout --`/discard on the same worktree destroys it or a teammate's uncommitted fix alongside it. Parallel-group item branches conflicting only on `.claude/dev-team/*-report.md` (add/add) is expected, not a sign the group overlapped. **How to apply:** put "write your report to `.claude/dev-team/<name>.md` as well as returning it" in every spawn prompt; `ls .claude/dev-team/` after each agent; `git add .claude/dev-team/` in the same commit that records the item's outcome; never discard a tree that might hold teammate work without a `cp` backup + `shasum -c` restore; resolve report-file conflicts with `--theirs`.

- 2026-07-21 Every agent that runs the test suite (not just QA) must be told the exact expected pass/skip counts and how to wire env — spawned agents get fresh shells, so env-gated integration files skip silently and a builder reports "tests pass" while the DB-backed half never ran. Separately, a criterion of "the script runs EVERY test file" can't be verified from the runner's own output (real `node:test` reports subtest names, not filenames). **How to apply:** state "expect N pass / M skip" in every spawn prompt that runs tests, taking the numbers from the Start Up preflight baseline rather than guessing; verify full-suite coverage claims by probe injection — append a deliberately throwing test to each suspect file, confirm totals move by exactly the injected count, restore from backup and verify with `shasum -c`.

- 2026-07-22 A QA test asserting a NEGATIVE side effect ("no row written when X") must drive the real production entry point, not re-derive the property from adapter calls — code comments claiming an ordering guarantee can be wrong. **How to apply:** in QA spawn prompts for any ordering/absence criterion, require the test to call the actual handler/action; cross-check comments claiming ordering against the literal statement order.

- 2026-07-22 When an item requires touching live *hosted* infra (remote endpoints, tokens — beyond the local ports the Start Up preflight already checks), the orchestrator should probe that capability itself before gating, rather than let QA discover an unfixable environment fact and FAIL toward a false BLOCKED. **How to apply:** ~2 minutes of nc/env probes converts an unfixable criterion into a verified-degraded gate; keep PROGRESS's claim scoped to what was actually verified.

- 2026-07-25 A library's deprecation `console.warn` is not evidence a feature is gated off — most SDKs emit it unconditionally for every caller. When an item's premise is "X is broken," the orchestrator should spend ~5 tool calls driving the real thing before spawning any builder. A research brief also describes the package registry, not your installed tree. **How to apply:** for any "feature X doesn't work" item, personally reproduce first (browser drive, curl, one query) and state the adjudicated root cause as ground truth in the builder's prompt; verify a recommended package/major actually exists in the lockfile before building on a research recommendation.

- 2026-07-25 When a criterion is "X must be UNCHANGED," the only honest gate is a true A/B against the actual pre-change build (`git stash` → rebuild → measure → `stash pop` → rebuild → measure) — never a post-hoc arithmetic justification of an observed delta, which is indistinguishable from a real regression without redoing the measurement. **How to apply:** require the before-leg to be measured on reverted code in the same session; treat any "the difference is accounted for by…" in a PASS verdict as an unfinished check.

- 2026-07-27 Before writing a PLAN.md, confirm a test runner is actually WIRED — the presence of test files proves nothing, and "existing passing tests remain passing" is vacuous when no command runs them. **How to apply:** during the codebase scan, grep `package.json`/CI config for the test entry point and try it once; if nothing runs the suite, make wiring it the first, low-risk item of the plan. Same probe for `lint`/`typecheck` when criteria lean on them.

- 2026-08-01 A gate returning "environmental drift, not our diff — don't fix" must be adjudicated against what the failing assertion actually observes, not its error message or its file's git diff — the proposed cause must be able to physically reach that observable. A differential inside the same file (a tolerance variant passing while the exact-point variant fails, at identical coordinates) points to staleness, not environment. Two contending test files in one run can also shift which tests fail. **How to apply:** ask what the observable literally is (a stub? a DOM read? a network effect?) before accepting an environment excuse; isolate contending test files before trusting a failure set.

- 2026-08-01 A `done light` / Quadrant-1 item (single builder, no QA, no review) can plant a flake that surfaces later, in a different file, as another item's regression — the item's own new tests all pass, so nothing local catches it. **How to apply:** when an item adds continuous motion, a per-frame loop, a timer, or global state to a surface other suites assert on (coordinates, colours, counts), treat it as cross-suite and round up out of Quadrant 1 — at minimum run the existing suites that touch that surface before marking it done.
